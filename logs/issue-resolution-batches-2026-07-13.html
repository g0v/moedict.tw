Safari 修正（提交 81d444b）

移除按鈕後，Safari／WebKit 出現版面錯亂： h1.title 被撐高至約 164 px，播放按鈕被推到詞目下方甚遠處， huáng 則出現在錄音按鈕下方。根本原因在於： WebKit 的排版引擎在其 ruby 文字方塊生成過程中，強制將 <rt> 設為 position: static，即使 CSS 與 JS 的 setProperty 皆設定了 position: absolute !important，也仍會被覆寫。 這種靜態定位使 <rt> 停留在正常的 ruby 排版流程中， 因而撐大 h1 並將音檔區塊與羅馬字向下推移， huáng 於是出現在錄音按鈕之後。

修正方式：ruby2hruby.ts 現在會在非注音的 rtc 轉換迴圈中， 直接從 rt.textContent 建構一個 <span class="romanization-selectable" aria-hidden="true">， 並由 src/index.css 套用 position: absolute; color: transparent; user-select: text。 同一個 <ru> 父層中的一般 <span>， 在所有引擎上都能正確接受 position: absolute。原生的 <rt> 絕不可再被還原承擔此角色： WebKit 的限制屬於引擎層級，無法透過作者端 CSS 覆寫。

最終證據： 523c7f9（移除按鈕）加上 81d444b（Safari 安全的 span 架構）。 WebKit 與 Chromium 各自 15/15 個 @romanization 測試皆通過，包含真實的滑鼠拖曳選取 （huáng、tsia̍h）、幾何不變性檢查 （疊加層位於 rb 列之上、h1 高度／字級比例 < 4、audioBlock 落於 h1 邊界內）、語音偏好設定的抑制，以及無重複的輔助技術報讀。
